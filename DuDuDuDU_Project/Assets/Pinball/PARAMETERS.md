# 파라미터 레퍼런스

## 좌표계

보드 **좌하단이 (0,0)**, y가 위쪽. 단위는 "유닛"이고 미터로 생각하면 된다.
기본 판은 6 × 10 유닛이다.

감을 잡는 가장 쉬운 방법은 **구슬 반지름 0.16을 잣대로 삼는 것**이다.

- 핀 반지름 0.11 → 구슬보다 조금 작다
- 핀 간격 0.79 → 구슬 지름의 약 2.5배. 구슬이 사이로 빠져나갈 수 있다
- 범퍼 0.30 → 구슬의 두 배. 눈에 띄게 크다

## 물리

### `gravity`

구슬을 아래로 당기는 힘. **연출 길이를 결정하는 1번 손잡이**다.

현실값 -9.8은 모바일 보상 연출엔 너무 느리다. 기본값은 -26.

| | |
|---|---|
| 올리면 (-30) | 빨리 떨어져 연출이 짧아짐. 대신 핀 충돌 수가 줄어 밋밋해짐 |
| 내리면 (-15) | 오래 떠 있어 화려하지만 한 판에 6초 넘음 |
| 함께 볼 값 | `launchSpeed` — 중력을 키우면 구슬이 위까지 못 올라가 폐기율이 급증한다 |

### `linearDrag`

초당 속도 감쇠율. 공기 저항이라고 보면 된다.

**0으로 두면 안 된다.** 구슬이 영원히 튀어서 `maxSteps`까지 가고 전부 폐기된다.

| | |
|---|---|
| 올리면 (0.6) | 빨리 잠잠해짐. 연출이 짧지만 핀 충돌이 줄어듦 |
| 내리면 (0.2) | 오래 튐. 화려하지만 길고, 구석에 끼는 경우도 늘어남 |
| 권장 | 0.3 ~ 0.5 |

### `ballRadius`

구슬 반지름. 단순히 크기가 아니라 **충돌 판정과 서브스텝 분할의 기준**이다.

핀 간격보다 충분히 작아야 구슬이 핀밭을 통과해 내려올 수 있다. 키우면 핀에 자주 걸려 폐기율이 오른다.

### `pegRestitution` / `wallRestitution`

반발계수. 1이면 에너지 손실 없이 완전탄성, 0이면 달라붙는다.

- 핀 0.86 근처가 "통통 튀는" 느낌
- **0.95 이상은 위험하다.** 구슬이 날뛰어 구석에 끼고 폐기율이 치솟는다
- 벽은 핀보다 낮게. 벽에 갇혀 진동하는 구슬이 줄어든다

개별 핀의 `restitution`을 0보다 크게 주면 그 핀만 다른 값을 쓴다. 기본 판은 중앙 범퍼 두 개를 0.92로 올려놨다. Sim Lab 캔버스에서 이런 핀은 **분홍색**으로 표시된다.

### `maxSpeed`

속도 상한. 수치가 폭주해 구슬이 판 밖으로 날아가는 걸 막는 안전장치다.
`launchSpeed`의 1.3배 이상으로 잡아라.

## 발사

### `launchSpeed`

**폐기율이 90%를 넘으면 제일 먼저 의심할 값이다.**

구슬이 발사 레인을 타고 올라가 상단 디플렉터 램프까지 닿아야 한다. 조금이라도 부족하면 레인 안에서 위아래로만 튀다 멈추고, **모든 시드가 폐기된다.** 처음 이 시스템을 만들 때 가장 흔하게 겪는 실패다.

### `angleJitterDeg` ★

**궤적 다양성의 핵심이자, 시드가 하는 일의 거의 전부다.**

시드는 발사 각도를 이 범위 안에서 흔드는 데만 쓰인다. 물리가 카오스적이라 ±2°만 흔들어도 착지 칸이 완전히 갈린다.

| | |
|---|---|
| 올리면 | 다양성 ↑. 대신 레인 벽에 긁혀 폐기되는 시드가 늘어남 |
| 내리면 | 궤적이 비슷비슷해져 특정 칸 풀이 말라붙음 |
| 언제 건드리나 | **특정 슬롯 풀이 비었을 때 제일 먼저 올려본다** |

### `speedJitter`

발사 속도의 흔들림 폭. 각도 지터를 보조한다.
너무 키우면 약하게 발사된 구슬이 레인을 못 넘어 폐기된다.

---

## 시뮬레이션

### `stepsPerSecond`

고정 스텝 주파수. `Time.deltaTime`은 시뮬에 절대 개입하지 않는다.

120이 정확도와 베이크 속도의 균형점이다.

> ⚠️ **이 값을 바꾸면 기존 시드 테이블이 전부 무효가 된다.**

### `maxSteps`

이 스텝을 넘기면 "끼임"으로 보고 시드를 폐기한다. 3000 = 25초.

폐기율이 높은데 원인을 모르겠으면 이 값을 늘려보라. 그래도 폐기되면 진짜로 끼인 것이고, 이 값을 줄여서 폐기되면 그냥 느린 것이다.

---

## 보상 칸

### `catchLineY`

구슬 중심이 이 y 아래로 내려오면 착지로 판정한다.

> ⚠️ **바닥 정지 높이(바닥 y + `ballRadius`)보다 충분히 위여야 한다.**
> 겹치면 구슬이 바닥에 앉은 뒤에도 판정이 안 나고 전부 폐기된다.
> Sim Lab이 이 조건을 검사해서 빨간 경고를 띄운다.

### `armHeightY`

발사 지점이 `catchLineY`보다 아래에 있기 때문에, **이 높이를 한 번 넘어야 착지 판정이 켜진다.**

이게 없으면 발사 첫 스텝에 곧바로 "착지"로 오판정된다. 핀밭 하단보다 살짝 아래로 잡으면 된다.

### `slotMinX` / `slotMaxX`

보상 칸 영역의 좌우 경계. 이 밖에서 캐치 라인을 지나면 무효 처리한다.
발사 레인으로 되돌아간 구슬을 걸러내는 용도다.

### `dividersX` / `dividerTopY` / `dividerBottomY`

칸 경계 좌표. n개면 슬롯은 n+1개다.

> **칸막이 벽은 이 값에서 자동 생성된다.** `segments`에 따로 넣지 마라.
> 물리와 판정이 어긋나는 걸 구조적으로 막기 위한 설계다.

`dividerTopY`를 높이면 칸이 깊어져 한번 들어간 구슬이 옆칸으로 못 넘어간다. 낮추면 니어미스 연출이 늘어난다.

### `declaredProbability`

**실제 지급은 이 확률표를 따른다.** 물리 판의 자연 분포와 일치할 필요가 전혀 없다.

기본 판의 자연 분포는 28 / 14.5 / 13 / 13.5 / 31%인데, 표기 확률은 20 / 22 / 16 / 22 / 20%다. 이건 정상이다. 시드 풀은 "그 칸으로 가는 예쁜 궤적"을 공급하는 역할만 한다.

합이 1.0이어야 하고, 슬롯 수와 길이가 같아야 한다.

## 증상별 진단표

| 증상 | 원인 | 조치 |
|---|---|---|
| 폐기율 90%↑ | 구슬이 레인을 못 벗어남 | `launchSpeed` ↑, 디플렉터 램프 확인 |
| 폐기율 90%↑, 발사 직후 즉시 착지 판정 | `armHeightY`가 너무 낮음 | `armHeightY`를 핀밭 아래로 올림 |
| 폐기율 100%, 구슬이 바닥에 앉아있음 | `catchLineY` ≤ 바닥 + `ballRadius` | `catchLineY` ↑ |
| 폐기율 30~50% | 구석에 끼임 | `linearDrag` ↑, `pegRestitution` ↓, `maxSteps` ↑ |
| 특정 슬롯 풀이 비거나 매우 적음 | 궤적 다양성 부족 | `angleJitterDeg` ↑, 그 칸 위 핀 배치 조정 |
| 평균 핀 충돌 12회 미만 | 밋밋함 | 핀 촘촘히, `linearDrag` ↓, `pegRestitution` ↑ |
| 평균 5초 초과 | 연출이 늘어짐 | `gravity`·`linearDrag` ↑ (`launchSpeed`도 함께) |
| 니어미스 10% 미만 | 아슬아슬함 부족 | `dividerTopY` ↓, 칸막이 위 핀 열 조정 |
| 구슬이 핀을 통과함 | 터널링 | `maxSpeed` ↓, `stepsPerSecond` ↑ |

## 튜닝 순서

한 번에 여러 값을 만지면 뭐가 효과였는지 알 수 없다. 이 순서를 권한다.

1. **판 모양부터 확정.** 외벽, 레인, 디플렉터를 먼저 그린다
2. **`launchSpeed`로 폐기율부터 잡는다.** 이게 안 되면 나머지는 의미가 없다
3. **핀밭을 배치한다.** 평균 핀 충돌 12회 이상이 목표
4. **`gravity` + `linearDrag`로 길이를 맞춘다.** 3~5초. 둘을 같이 움직여라
5. **`angleJitterDeg`로 슬롯별 풀을 채운다.** 모든 칸이 최소 표본을 넘을 때까지
6. **`dividerTopY`로 니어미스를 조율한다.** 10% 이상
7. 그 다음에 Bake

각 단계마다 Sim Lab의 **Quick Test**를 돌려라. 2,000판이 1초 안에 끝나고, 합격 기준 미달이면 무엇을 만져야 하는지 문장으로 알려준다.

## Sim Lab 사용법

### Edit Board 탭

| 도구 | 조작 |
|---|---|
| **Move** | 핀·벽 끝점·칸막이·발사점을 드래그. 핀 위에서 **휠**을 굴리면 크기 변경 |
| **+ Peg** | 클릭해서 핀 추가. 휠로 새 핀의 크기 조절 |
| **+ Wall** | 두 번 클릭해서 벽 생성. Esc로 취소 |
| **Erase** | 클릭해서 핀/벽 삭제 |

어느 도구에서든 **Alt+클릭**으로 바로 삭제된다. 모든 편집은 **Ctrl+Z로 되돌릴 수 있다.**

Snap을 켜면 격자에 맞춰 배치된다. 격자 간격이 0.2 이상일 때만 캔버스에 눈금이 그려진다.

**핀 생성기**로 지그재그 격자나 가로 한 줄을 한 번에 만들 수 있고, 좌우 대칭 복사도 된다. 대칭 판을 만들 땐 왼쪽 절반만 그리고 "좌→우 대칭"을 누르면 된다.

### 캔버스에서 보이는 것

- **주황 선** — 편집 가능한 벽
- **초록 선** — 자동 생성된 칸막이 (편집 대상 아님, 경계 좌표를 드래그해서 옮긴다)
- **분홍 원** — 반발계수를 따로 준 핀 (범퍼)
- **빨간 점 + 부채꼴** — 발사 지점과 각도 지터 범위. 지터를 얼마나 줬는지 눈으로 보인다
- **초록 가로선 (catch)** — 착지 판정선
- **노란 가로선 (arm)** — 착지 판정이 켜지는 높이
- 칸 아래 **백분율** — Quick Test를 돌린 뒤 표시되는 자연 분포

### Preview 탭의 Overlay

"Overlay 30 Random Paths"를 누르면 궤적 30개가 겹쳐 그려진다.
**핀 배치가 구슬을 어디로 몰고 있는지 한눈에 보이기 때문에**, 특정 칸 풀이 마를 때 원인을 찾는 데 제일 빠르다.

## UI 프리팹 설정

`prefabSettings` 는 시뮬에 전혀 영향이 없으므로 **LayoutHash 에 포함되지 않습니다.**
색만 바꿨다고 시드 테이블이 무효가 되면 곤란하니까요.

| 필드 | 설명 |
|---|---|
| `pixelsPerUnit` | 보드 1유닛이 UI 픽셀 몇 개인지. 6유닛 × 100 = 600px |
| `wallThicknessPx` | 벽·칸막이 두께 |
| `pegSprite` 외 | 비워두면 Unity 기본 UI 스프라이트. 아트가 나오면 꽂고 다시 굽는다 |
| `bumperColor` | 개별 반발계수를 준 핀에만 적용 |
| `createSlotAreas` | 보상 칸마다 빈 영역 생성. 아이콘·수량을 자식으로 붙이는 자리 |
| `pegPunchScale` | 핀에 맞았을 때 튀어오르는 배율 |
| `pegPunchDuration` | 튀었다 돌아오는 시간 |

타격 세기는 `HitEvent.impact`(충돌 직전 법선 속도)를 `impactReference` 로 나눠 0~1 로 정규화됩니다.
세게 맞으면 크게 튀고, 스치면 살짝 움직입니다.
