# 패키지 · 상점 UI 기획서 (초안)

> 패키지는 로비에서 먼저 말을 걸고, 상점은 유저가 필요할 때 찾아오는 창고다

| 항목 | 내용 |
|---|---|
| 문서 범위 | 로비 HUD 진입 동선 / 패키지 4종 / 상점 7개 섹션 |
| 상위 문서 | BM 설계 기획서 — 가격·회수 구조는 해당 문서를 따른다 |
| 기준 재화 | 유료젬 (10원 = 1젬), 무료젬 |
| 레이아웃 레퍼런스 | 카피바라, 협곡의 타디 (이하 "협타디") |
| 문서 상태 | 초안, 수치 및 상품 구성 미확정 (10장 참고) |

---

## 1. 설계 원칙

### 1.1 패키지와 상점의 역할 분리

두 화면은 같은 결제 UI지만 역할이 다르다. 이 구분이 흐려지면 로비가 광고판이 되거나, 상점이 팔리지 않는 창고가 된다.

| 구분 | 패키지 | 상점 |
|---|---|---|
| 진입 | 로비 HUD 버튼 (항상 노출) | 로비 하단 탭 `LobbyTab.Shop` |
| 성격 | **푸시** — 게임이 유저에게 먼저 제안한다 | **풀** — 유저가 필요해서 찾아온다 |
| 상품 수명 | 기간 한정 (30일 / 7일 / 수 시간) | 상시 |
| 결제 수단 | 대부분 현금(IAP) | 현금 + 게임 재화 혼합 |
| 핵심 지표 | 노출 대비 구매 전환 | 재화 소비 순환 |

### 1.2 노출 원칙

BM 문서 1.1의 *"초반부터 패키지를 덕지덕지 붙이지 않는다"* 원칙을 UI로 옮기면 다음과 같다.

1. **로비 HUD 버튼은 최대 4개까지만 둔다.** 그 이상은 아이콘 자체가 배경이 된다.
2. **팝업 자동 노출은 하루 1회, 1종만 한다.** 나머지는 HUD 아이콘의 레드닷으로만 알린다.
3. **미구매 상태에서도 "이미 쌓인 내 보상"을 계속 보여준다.** 특별한 7일의 핵심 장치이며, 시즌 패스에도 동일하게 적용한다.
4. **구매 완료된 상품의 아이콘은 즉시 내린다.** 광고제거권처럼 영구 상품은 구매 시 HUD에서 사라진다.

## 2. 로비 HUD 진입 동선

### 2.1 배치

![레퍼런스 — 시즌 패스는 상단 가로 바, VIP·돌발 패키지는 좌측 세로 스택으로 분리되어 있다](images/%EB%A1%9C%EB%B9%84%20Hud.png){: .shot }

**우리 안**

```text
+----------------------------------------------+
|  [골드] [무료젬] [유료젬] [고기]      [설정] |  <- 재화 HUD
+----------------------------------------------+
| +----+                                       |
| |패스|*                                      |  <- 패키지 진입 버튼
| +----+                                       |     (좌측 세로 스택)
| | 7일|*                                      |
| +----+                                       |
| |멤버|                                       |
| +----+                                       |
| |돌발|05:21                                  |
| +----+                                       |
|                                              |
|                [ 스테이지 ]                  |
|                                              |
|              <    12-3    >                  |
|              [    입 장    ]                 |
+----------------------------------------------+
|   홈  | 상점 | 장비 | 총알 | 도우미          |  <- LobbyTab
+----------------------------------------------+
```

좌측 세로 스택을 쓰는 이유는 스테이지 입장 동선(중앙 하단)과 겹치지 않으면서, 로비 진입 시 시선이 처음 지나가는 자리이기 때문이다.

**레퍼런스와의 차이**

레퍼런스는 시즌 패스만 **상단 가로 바**로 빼고, VIP와 돌발 패키지는 좌측 세로 스택에 뒀다. 패스는 진행률(720/1000)과 잔여 기간을 항상 보여줘야 해서 아이콘 하나로는 담기지 않기 때문이다.

우리도 같은 문제를 갖는다. 시즌 패스를 좌측 스택에 두면 레벨과 진행률을 배지로 압축해야 한다. 아래 둘 중 하나를 골라야 한다.

| 안 | 내용 | 장단 |
|---|---|---|
| A. 스택 유지 | 4개 모두 좌측 세로 스택 | 진입 동선이 한 곳에 모인다. 대신 패스 진행률을 못 보여준다 |
| B. 패스만 분리 | 패스는 상단 가로 바, 나머지 3개는 좌측 스택 | 진행률·잔여 기간 노출. 대신 상단 재화 HUD 아래 공간을 더 먹는다 |

**미정.** 위 목업은 A안 기준이다.

### 2.2 버튼 규격

| 순서 | 버튼 | 배지 | 노출 조건 |
|---|---|---|---|
| 1 | 시즌 패스 | 수령 가능 시 레드닷 | 시즌 진행 중 상시 |
| 2 | 특별한 7일 | 수령 가능 시 레드닷 | 오픈 후 7일간, 또는 미수령 보상 존재 시 |
| 3 | 멤버십 | 만료 3일 전부터 `D-n` | 상시 (2종 모두 보유 시 숨김) |
| 4 | 돌발 패키지 | 최단 잔여 시간 타이머 | 활성 패키지 1개 이상일 때만 |

- 모든 버튼은 아이콘 + 배지 구조를 공유한다. 기존 `UIIdleRewardLobbyButton`의 `button + progressText + redDot` 패턴을 그대로 재사용한다.
- 버튼이 4개 미만이면 스택은 위에서부터 채우고 아래를 비운다. 위치를 고정하지 않는다.

### 2.3 자동 노출 우선순위

로비 진입 시 팝업을 띄울 후보가 여러 개면 아래 순서로 **1개만** 띄운다.

```text
1. 돌발 패키지  (신규 발생, 최초 1회)
2. 특별한 7일   (오늘자 미수령 보상 존재)
3. 시즌 패스    (신규 시즌 시작일)
4. 멤버십       (만료 당일)
```

같은 팝업은 하루 1회만 자동 노출한다. 이후에는 HUD 아이콘으로만 접근한다.

## 3. 패키지 — 시즌 패스

| 항목 | 내용 |
|---|---|
| 주기 | 30일 로테이션 |
| 구조 | 무료 트랙 / 유료 트랙 2단 |
| 보상 재화 | 소환권, 강화권, 골드, 특별돌, 신화돌 |
| 가격 | 미정 (10장 참고) |

### 3.1 레이아웃

![레퍼런스 — 중앙 레벨 노드를 기준으로 무료·유료 트랙을 좌우로 나누고 세로로 스크롤한다. 상단에 시즌명·잔여 기간·진행바, 하단에 일괄 수령](images/%EC%8B%9C%EC%A6%8C%20%ED%8C%A8%EC%8A%A4.png){: .shot }

**우리 안**

```text
+--------------------------------------------------+
|  시즌 패스            시즌 종료까지 12일 04:31   |
+--------------------------------------------------+
|  [==================......]  레벨 14 / 30        |
|  다음 레벨까지 320 / 500 P                       |
+--------------------------------------------------+
|           1       2       3       4       5      |
|  무료   [소환]  [골드]  [강화]  [골드]  [특별]   |  <- 가로 스크롤
|         ------  ------  ------  ------  ------   |
|  유료   [신화]  [소환]  [특별]  [강화]  [신화]   |
|          수령    수령    수령    잠김    잠김    |
+--------------------------------------------------+
|  [ 유료 트랙 구매 ]            [ 모두 받기 ]     |
+--------------------------------------------------+
```

**레퍼런스와의 차이**

레퍼런스는 중앙 레벨 노드를 축으로 무료·유료 트랙을 **좌우로 나누고 세로 스크롤**한다. 위 목업은 트랙을 상하로 두고 가로 스크롤하는 구조다.

세로 스크롤이 유리한 지점이 분명하다.

1. 모바일 세로 화면에서 한 번에 보이는 레벨 수가 더 많다.
2. 무료·유료가 좌우로 붙어 있어 **같은 레벨에서 무엇을 더 받는지** 바로 비교된다. 유료 트랙 구매 근거가 시각적으로 만들어진다.
3. 레벨이 30개까지 늘어나도 스크롤 방향이 화면 형태와 맞는다.

**세로 스크롤 2열을 권장한다.** 확정되면 위 목업을 교체한다.

### 3.2 동작 규칙

1. **무료 트랙은 미구매 유저도 즉시 수령한다.** 패스가 결제 UI가 아니라 성장 트랙으로 먼저 인식되게 만든다.
2. **유료 트랙 보상은 미구매 상태에서도 계속 적립된다.** 구매하는 순간 그동안 쌓인 보상을 한 번에 수령한다. 특별한 7일과 동일한 장치이며, 결제 시점을 시즌 내내 열어두기 위한 구조다.
3. **`모두 받기`는 수령 가능한 모든 보상을 한 번에 처리한다.** 획득 연출은 통합 팝업 1개로 묶는다.
4. **시즌 종료 시 미수령 보상은 소멸한다.** 종료 3일 전부터 배너로 경고한다.
5. **시즌 로테이션은 보상 테이블만 교체한다.** 레벨 구조와 필요 포인트는 시즌 간 동일하게 유지한다.

### 3.3 보상 재화 매핑

기획 용어와 현재 코드의 `PointType`(`Define.cs`) 대응은 아래와 같다. **확정 전 검토 필요.**

| 기획 용어 | 대응 `PointType` | 비고 |
|---|---|---|
| 소환권 | `NormalScroll` ~ `ThunderScroll` | 속성별 5종 |
| 강화권 | `WeaponScroll` ~ `NecklaceScroll` | 부위별 6종 |
| 골드 | `Gold` | — |
| 특별돌 | `SpecialDiceCore` | — |
| 신화돌 | `MythicScroll` | 명칭 정리 필요 (`Scroll` 계열과 성격이 다름) |

### 3.4 패스 포인트 획득처

패스 레벨을 올리는 포인트의 획득처는 아래로 한정한다. 획득처가 넓어지면 30일을 채우지 못하는 유저가 생긴다.

| 획득처 | 성격 |
|---|---|
| 스테이지 클리어 | 주 획득처 |
| 일일 미션 | 매일 방문 유도 |
| 주간 미션 | 이탈 복귀 보정 |

## 4. 패키지 — 특별한 7일

| 항목 | 내용 |
|---|---|
| 가격 | 8,000원 (800유료젬) |
| 기간 | 7일 출석 시 전 보상 수령 완료 |
| 레퍼런스 | 모비노기 출석 미션 |
| 레이아웃 변경점 | **7칸을 1줄로 배치** |

상품 설계와 회수 구조는 BM 설계 기획서 6장을 따른다. 본 문서는 UI만 다룬다.

### 4.1 레이아웃

![레퍼런스(모비노기 계열 출석 미션) — 2열 그리드에 일차가 쌓여 총량이 한눈에 들어오지 않는다. 우리는 이 구성을 1줄로 압축한다](images/%ED%8A%B9%EB%B3%84%ED%95%9C%207%EC%9D%BC.png)

**우리 안**

```text
+-------------------------------------------------------+
|  특별한 7일                                      [X]  |
+-------------------------------------------------------+
|  출석만 하면 8,000원어치 유료젬을 그대로 돌려받습니다 |
+-------------------------------------------------------+
|  +---++---++---++---++---++---++---+                  |
|  | 젬||선물|| 젬||선물||선물||선물||선물|             |  <- 1줄 고정
|  |300|| ? ||500|| ? || ? || ? || ? |                  |
|  +---++---++---++---++---++---++---+                  |
|   완료  완료  오늘   D4   D5   D6   D7                |
+-------------------------------------------------------+
|            [ 8,000원 . 구매하고 받기 ]                |
+-------------------------------------------------------+
```

### 4.2 1줄 배치의 조건

7칸을 1줄에 넣으면 칸 하나의 폭이 좁아진다. 그래도 1줄을 유지하는 이유는 **"7일이면 끝난다"는 총량이 한눈에 들어와야** 하기 때문이다. 대신 아래를 지킨다.

1. 칸 안에는 **아이콘과 수량만** 넣는다. 재화 이름은 넣지 않는다.
2. 1일차·3일차 젬 보상은 다른 칸보다 **테두리를 강조**한다. 회수 구조의 핵심이므로 시선이 여기 먼저 닿아야 한다.
3. 칸을 탭하면 해당 일차 보상의 상세 툴팁을 띄운다.
4. 가로 스크롤을 쓰지 않는다. 스크롤이 생기는 순간 총량 인지라는 목적이 사라진다.

### 4.3 상태별 표기

| 상태 | 칸 표기 | 조건 |
|---|---|---|
| 수령 완료 | 체크 오버레이, 채도 하향 | 구매 후 수령함 |
| 오늘 수령 가능 | 하이라이트 + 펄스 | 구매 후 당일 미수령 |
| 적립됨 (미구매) | 자물쇠 + 수량 노출 | **미구매 상태에서도 수량은 보여준다** |
| 미도래 | `D+n` 표기, 회색 | — |

미구매 유저에게 자물쇠만 보여주고 수량을 가리면 "이미 쌓인 내 보상"이라는 인식이 생기지 않는다. 수량은 항상 노출한다.

## 5. 패키지 — 멤버십

| 상품 | 가격 | 기간 | 효과 |
|---|---|---|---|
| 광고제거권 | 3,000원 (300젬) | 무제한 | 광고 제거 (그 외 혜택 없음) |
| 고기 멤버십 | 5,000원 (500젬) | 30일 | 스테이지 입장 고기 면제 + 소탕 횟수 무제한 |

### 5.1 레이아웃

![레퍼런스 — 카드 2장 세로 배치, 카드마다 혜택 목록과 가격 버튼, 하단에 환불 안내](images/%EB%A7%B4%EB%B2%84%EC%8B%AD.png){: .shot }

**우리 안**

```text
+----------------------------------------------+
|  멤버십                                  [X] |
+----------------------------------------------+
|  +----------------------------------------+  |
|  | 광고제거권                      무제한 |  |
|  | . 모든 광고 제거                       |  |
|  |                       [ 3,000원 ]      |  |
|  +----------------------------------------+  |
|  +----------------------------------------+  |
|  | 고기 멤버십                     30일권 |  |
|  | . 스테이지 입장 고기 0                 |  |
|  | . 소탕 횟수 무제한                     |  |
|  |                       [ 5,000원 ]      |  |
|  +----------------------------------------+  |
+----------------------------------------------+
```

**레퍼런스와의 차이**

레퍼런스는 카드 한 장에 혜택을 4~5줄씩 채웠다. 우리는 반대로 간다. 광고제거권 1줄, 고기 멤버십 2줄로 **의도적으로 줄인다.** 근거는 아래 5.2를 따른다.

다만 레퍼런스에서 가져올 것이 하나 있다. 하단의 **환불 안내 문구**다. 스토어 정책상 필요하고, 있는 편이 오히려 결제 신뢰를 만든다.

### 5.2 표기 규칙

1. **광고제거권 카드에는 부가 혜택을 한 줄도 넣지 않는다.** BM 문서 4장의 *"여기서 조금이라도 더 먹으려고 개수작 부리지 않는다"* 원칙을 UI에서도 지킨다. 혜택 문구가 늘어나면 "싸고 정직한 첫 결제"라는 역할이 사라진다.
2. **고기 멤버십은 혜택을 2줄로 고정한다.** 입장 고기 면제와 소탕 무제한 외에는 붙이지 않는다.
3. **구매 완료 시 카드는 목록에서 내린다.** 광고제거권은 영구 제거, 고기 멤버십은 `잔여 n일` 표기 카드로 대체한다.
4. **고기 멤버십 만료 3일 전부터 재구매 버튼을 노출한다.** HUD 배지도 이때부터 `D-n`으로 바뀐다.

## 6. 패키지 — 돌발 패키지

| 항목 | 내용 |
|---|---|
| 성격 | 조건 충족 시 발생하는 한시 판매 상품 |
| 노출 | HUD 아이콘 (활성 1개 이상일 때만) |
| 정렬 | **잔여 시간이 가장 짧은 것부터** |

### 6.1 단일 뷰 (아이콘 클릭 시)

```text
+----------------------------------------------+
|  돌발 패키지                    [목록]   [X] |
+----------------------------------------------+
|                                              |
|  <      +------------------------+      >    |
|         |    3렙 신화 패키지     |           |
|         |  --------------------  |           |
|         |  유료젬 250            |           |
|         |  신화석 15             |           |
|         |  --------------------  |           |
|         |  남은 시간 05:21:44  |             |
|         |      [ 5,000원 ]       |           |
|         +------------------------+           |
|                   * o o                      |
+----------------------------------------------+
```

1. 아이콘을 누르면 **잔여 시간이 가장 짧은 패키지**가 먼저 나온다.
2. 좌우 화살표로 다음 패키지를 넘긴다. 순서는 잔여 시간 오름차순이며, 마지막에서 처음으로 순환하지 않는다(양 끝에서 화살표 비활성).
3. 하단 인디케이터로 전체 개수와 현재 위치를 표시한다.

### 6.2 목록 뷰 (`목록` 버튼)

```text
+------------------------------------------------+
|  돌발 패키지 목록                          [X] |
+------------------------------------------------+
| +--------------------------------------------+ |
| | [썸네일] 3렙 신화 패키지                   | |
| |          젬250 + 신화석15  05:21   5,000원|  |
| +--------------------------------------------+ |
| | [썸네일] 장비 강화 지원                    | |
| |          젬100 + 강화권20  11:04   1,000원|  |
| +--------------------------------------------+ |
| | [썸네일] 주말 골드                         | |
| |          골드 500만       1일 22:10 3,000원| |
| +--------------------------------------------+ |
+------------------------------------------------+
```

목록에서 항목을 누르면 해당 패키지의 단일 뷰로 이동한다.

### 6.3 발생·만료 규칙

| 항목 | 규칙 |
|---|---|
| 동시 활성 상한 | 3개 (초과 발생 시 신규 발생 보류) |
| 발생 트리거 | 성장 구간 도달, 특정 콘텐츠 최초 클리어, 복귀 등 (구체 조건 미정) |
| 만료 | 잔여 시간 0 도달 시 목록에서 제거 |
| 만료 임박 | 잔여 1시간 미만이면 HUD 타이머를 강조 색으로 표기 |
| 재발생 | 동일 패키지는 미구매 시에도 일정 기간 재발생 없음 (쿨타임 미정) |

동시 활성 상한을 3개로 잡는 이유는 화살표 넘김이 2~3회를 넘어가면 유저가 끝까지 보지 않기 때문이다. 그 이상 필요해지면 상한을 늘리는 게 아니라 발생 조건을 좁힌다.

## 7. 상점 — 전체 구조

### 7.1 섹션 구성

상점은 하단 탭 `LobbyTab.Shop`으로 진입하며, 세로 1열 스크롤에 아래 순서로 섹션을 쌓는다.

| 순서 | 섹션 | 지불 수단 | 성격 |
|---|---|---|---|
| 1 | 성장 패키지 | 현금 | 대형 배너 |
| 2 | 보석뽑기 | 미정 | 뽑기 |
| 3 | 일일상점 | 게임 재화 | 순환 |
| 4 | 유료젬 상점 | 현금 | 재화 충전 |
| 5 | 무료젬 상점 | 유료젬 | 재화 교환 |
| 6 | 다이스석 상점 | 무료젬 | 재화 교환 |
| 7 | 골드 상점 | 무료젬 | 재화 교환 |

### 7.2 배치 근거

카피바라·협타디 계열 상점의 공통 구조를 그대로 가져온다.

1. **최상단은 현금 상품, 최하단은 재화 교환.** 위에서 아래로 내려갈수록 결제 부담이 낮아진다.
2. **1번 섹션은 스크롤 없이 전체가 보인다.** 상점에 들어온 유저가 가장 먼저 보는 화면은 성장 패키지 배너 하나뿐이어야 한다.
3. **3번 일일상점은 매일 리셋되므로 재방문 앵커다.** 상단 3개 섹션 안에 둔다.
4. **4~7번은 목적을 갖고 찾아오는 섹션이다.** 스크롤 아래에 있어도 무방하며, 재화 HUD를 탭하면 해당 섹션으로 바로 스크롤한다.

### 7.3 재화 흐름

```text
                    현금
                     |
                     +----------> 성장 패키지 (유료젬 + 성장 재화)
                     |
                     v
                  유료젬 --------> 무료젬
                                     |
                     +---------------+---------------+
                     |               |               |
                     v               v               v
                   신화석          레어석           골드
                     |               |               |
                     +------- 다이스 . 장비 성장 ----+
```

유료젬은 **아래로만 흐른다.** 무료젬을 유료젬으로 되돌리는 경로는 만들지 않는다. 이 방향성이 깨지면 BM 문서 2장의 `10원 = 1유료젬` 환산 기준이 무너진다.

## 8. 상점 섹션 상세

### 8.1 성장 패키지

| 항목 | 내용 |
|---|---|
| 표현 | 대형 가로 배너 (상점 최상단, 화면 폭 전체) |
| 구성 원칙 | **유료젬 + 성장 재화** 조합 |
| 노출 기준 | 유저의 현재 성장 단계에 맞는 상품만 노출 |

```text
+----------------------------------------------+
| +==========================================+ |
| |  [대형 배너 아트]                        | |
| |                                          | |
| |  스타트 패키지                           | |
| |  유료젬 300 + 부위별 Rare 보석           | |
| |                                          | |
| |  남은 시간 2일 04:12   [ 3,000원 ]     |   |
| +==========================================+ |
|                    * o                       |
+----------------------------------------------+
```

**상품 예시**

| 상품 | 가격 | 구성 | 노출 조건 |
|---|---|---|---|
| 스타트 패키지 | 3,000원 | 유료젬 300 + 부위별 Rare 보석 | 최초 진입 후 |
| 3렙 신화 패키지 | 5,000원 | 유료젬 250 + 신화석 15 | 신화 다이스 3레벨 도달 |

**설계 규칙**

1. **배너는 공간을 크게 차지한다.** 이 섹션의 목적은 정보 전달이 아니라 시선 점유다. 작게 줄여 여러 개를 나열하지 않는다.
2. **동시 노출은 최대 2개.** 그 이상은 가로 스와이프로도 끝까지 보지 않는다.
3. **구성품에 유료젬을 반드시 포함한다.** 유저가 `10원 = 1젬` 기준으로 가격을 즉시 환산할 수 있어야 한다. 예시의 스타트 패키지는 3,000원 중 3,000원어치가 젬이므로 보석은 전액 덤으로 읽힌다.
4. **성장 단계를 지나면 상품을 내린다.** 지나간 단계의 패키지가 남아 있으면 배너 전체가 무시된다.

### 8.2 보석뽑기

| 상자 | 등장 등급 | 지불 재화 |
|---|---|---|
| 일반 보석 상자 | `Common` · `Normal` · `Rare` | 미정 |
| 최고급 보석 상자 | `Normal` · `Rare` · `Epic` | 미정 |

```text
+----------------------------------------------+
|  보석뽑기                                    |
| +--------------------++--------------------+ |
| |   일반 보석 상자   ||  최고급 보석 상자  | |
| |   [상자 아트]      ||  [상자 아트]       | |
| |  Com / Nor / Rare  ||  Nor / Rare / Epic | |
| |   [확률 보기]      ||  [확률 보기]       | |
| |  [1회]    [10회]   ||  [1회]    [10회]   | |
| +--------------------++--------------------+ |
+----------------------------------------------+
```

**설계 규칙**

1. 등급 체계는 기존 `Rarity` enum(`Define.cs`)을 그대로 쓴다. 보석 정의는 `GemDefinitionDatabase`의 `GemDefinition.rarity`를 참조한다.
2. **두 상자는 등급 구간이 한 칸 겹친다**(`Normal`, `Rare`). 상위 상자를 사는 이유가 "`Epic`이 나온다"로 단순해야 하고, 하위 상자를 계속 쓰는 이유도 남아야 한다.
3. 1회 / 10회 버튼을 나란히 둔다. 10회 할인 여부는 미정.
4. **확률 표기는 상자 카드 안에 상시 노출한다.** 별도 화면으로 숨기지 않는다.
5. 10회 결과는 그리드 연출로 한 번에 보여주고, 최고 등급만 강조한다.

### 8.3 일일상점

| 항목 | 내용 |
|---|---|
| 레퍼런스 | 협타디, 운빨 계열 상점 |
| 방침 | **레이아웃 및 기능을 그대로 흡수한다** |
| IAP 여부 | 아님 (게임 재화 전용) |

```text
+-------------------------------------------------+
|  일일상점             갱신까지 07:12:33  [갱신] |
| +--------++--------++--------+                  |
| |  소환권 ||   골드  ||   보석  |               |
| |    x5   ||   10만  ||   Rare  |               |
| |  젬 50  ||  젬 30  ||  젬 200 |               |
| +--------++--------++--------+                  |
| +--------++--------++--------+                  |
| |  강화권 ||  특별돌 ||   골드  |               |
| |   x10   ||    x3   ||   30만  |               |
| |  젬 80  ||  젬 150 ||  젬 70  |               |
| +--------++--------++--------+                  |
+-------------------------------------------------+
```

**흡수 대상 기능**

| 기능 | 규칙 |
|---|---|
| 슬롯 수 | 6칸 고정 (2행 × 3열) |
| 자동 갱신 | 매일 정해진 시각 1회 |
| 수동 갱신 | 광고 시청 또는 재화 지불 (횟수 제한, 수치 미정) |
| 구매 완료 | 슬롯을 비우지 않고 `SOLD` 오버레이로 남긴다 |
| 등급 연출 | 고등급 슬롯은 프레임 색과 배경 이펙트로 구분 |
| 할인 표기 | 확률적으로 할인 슬롯 등장 |

구매 완료 슬롯을 비우지 않고 `SOLD`로 남기는 이유는, 빈 칸이 생기면 오늘 상점이 끝났다는 인상을 줘서 남은 슬롯을 보지 않기 때문이다.

### 8.4 유료젬 상점

| 항목 | 내용 |
|---|---|
| 지불 | 현금 (IAP) |
| 환산 | 10원 = 1유료젬 |
| 묶음 할인 | **없음** |

```text
+----------------------------------------------+
|  유료젬 상점                                 |
| +------------------------------------------+ |
| | 젬   100 유료젬                  1,000원 | |
| | 젬   300 유료젬                  3,000원 | |
| | 젬   500 유료젬                  5,000원 | |
| | 젬 1,000 유료젬                 10,000원 | |
| | 젬 3,000 유료젬                 30,000원 | |
| +------------------------------------------+ |
+----------------------------------------------+
```

**설계 규칙**

1. **묶음 할인을 넣지 않는다.** BM 문서 2장의 근거를 그대로 따른다. 300젬 = 3,000원이 고정이어야 출석 보상 300젬이 광고제거권 하나 값으로 읽힌다.
2. 할인이 없으므로 `+보너스` 뱃지나 `최대 이득` 라벨도 넣지 않는다. **가격표는 정직한 환산표로만 보이게 한다.**
3. 300젬·500젬 상품은 각각 광고제거권·고기 멤버십과 금액이 일치한다. 이 두 줄에 **해당 상품 아이콘을 작게 병기**해서 환산을 눈으로 잇는다.
4. 판매 단위 구성(위 예시 5종)은 **미정**이다.

### 8.5 무료젬 상점

| 항목 | 내용 |
|---|---|
| 지불 | 유료젬 |
| 획득 | 무료젬 |

유료젬을 게임 내 소비 재화로 전환하는 유일한 관문이다. 다이스석 상점과 골드 상점은 모두 무료젬을 요구하므로, 실질적으로 **모든 현금 흐름이 이 섹션을 통과**한다.

**설계 규칙**

1. 교환비는 단일 고정값으로 둔다. 구간별 우대 교환비를 넣으면 유료젬 무할인 원칙이 우회로로 무너진다.
2. 교환 실행 시 확인 팝업을 띄운다. 되돌릴 수 없는 방향이므로 오조작을 막는다.
3. 교환비 수치는 **미정**.

### 8.6 다이스석 상점

| 상품 | 지불 |
|---|---|
| 신화석 | 무료젬 |
| 레어석 | 무료젬 |

```text
+----------------------------------------------+
|  다이스석 상점                               |
| +--------------------++--------------------+ |
| |      신화석        ||      레어석        | |
| |   [아이콘]   x10   ||   [아이콘]   x10   | |
| |      젬 미정       ||      젬 미정       | |
| |   오늘 구매 0 / n  ||   오늘 구매 0 / n  | |
| +--------------------++--------------------+ |
+----------------------------------------------+
```

**설계 규칙**

1. **일일 구매 한도를 둔다.** 한도가 없으면 무료젬 보유량이 그대로 스펙이 되어 성장 곡선이 무너진다. 한도 수치는 미정.
2. 구매 횟수가 늘어날수록 단가가 오르는 누진 구조를 검토한다(미정).
3. 신화석과 레어석의 단가는 다이스 성장 소요량 비율에 맞춘다.

### 8.7 골드 상점

| 상품 | 지불 |
|---|---|
| 골드 | 무료젬 |

**설계 규칙**

1. 골드는 상시 부족한 범용 재화이므로 **한도 없이 판매**한다. 다이스석과 달리 스펙에 직접 꽂히지 않는다.
2. 구매 횟수에 따라 단가가 오르는 누진 구조를 적용한다. 무료젬이 골드로만 빠져나가는 것을 막는다.
3. 판매 단위와 단가는 **미정**.

## 9. 구현 시 확인이 필요한 사항

현재 코드 기준으로 본 문서를 구현하려면 아래가 선행되어야 한다.

| 항목 | 현재 상태 | 필요 작업 |
|---|---|---|
| 유료젬 / 무료젬 분리 | `PointType.Dia` 1종만 존재 | **2종으로 분리 필수.** 무료젬 상점(8.5)이 성립하려면 별개 재화여야 한다 |
| 신화석 · 레어석 | `PointType`에 없음 | 신규 추가 필요 |
| 재화 표시명 | `PointMetadataDatabase.asset`의 `displayName`이 전부 영문 enum명 | 한글 표시명 및 아이콘 등록 필요 |
| 신화돌 / 신화석 용어 | `MythicScroll` 하나뿐 | 패스 보상(신화돌)과 다이스석 상점(신화석)이 같은 재화인지 확정 필요 |
